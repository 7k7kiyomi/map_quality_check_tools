## 3. `map_check_task_manager.cpp`

### 3.1 新增依赖与数据结构

相对于上述备份，增加 `right_angle_shared_tasks.h`、`water_result_classification.h`、`check_result_replacement.h` 及哈希、临时目录、QGIS 要素/几何/写出等头文件。

在约第 470 行起增加：

- `WaterTaskRun`：保存检查 ID、图层名、任务分组键、共享键、严重程度、临时结果路径、完整 `CheckItemResult` 和错误 JSON 等，供所有相关任务结束后汇总。
- `WaterErrorFeature`：保存错误要素、所属任务组、检查 ID、归类结果、指纹、坐标系以及类别冲突状态。

这里保存的是算法产生的结果及元数据；结构体本身不判断河流走向或铁路拓扑。

### 3.2 中间目录与任务分组

- 新增 `createWaterWorkDirectory(...)`：检查规范化绝对路径，优先在系统临时目录或缓存目录创建 `.water_task_results_XXXXXX`，且要求它不位于本次用户选择的输出根目录之下。无法创建时任务抛出异常，不回退到会被扫描的输出目录。
- 新增 `isWaterStandardTask(...)`：按标准图层名及成果 SHP 名称中的“河、水系、渠”等文本识别需要统一处理的 105／112 水系任务。
- 新增 `waterTaskGroupKey(...)`：按检查 ID 和标准化、排序去重后的成果输入路径生成汇总分组键。这个键用于汇总，**不等同于**是否可以复用算法运行的键。
- `executeAlgorithms(...)` 中新增 `waterTaskRuns`、`sharedWaterTaskOwners` 和临时目录对象；同一地图每次执行分别初始化，生命周期内保留完整错误记录。

### 3.3 水系算法执行结果复用

在 `executeAlgorithms(...)` 的普通检查分支中：

1. 对识别出的水系 105／112 任务调用 `LineTopologySharedTasks::waterTaskKey(...)`。共享键由辅助文件根据检查类型、成果与库体文件签名、比例尺、对应 XML 规则和 CSV 内容等生成；不满足条件返回空键，不复用。
2. 命中已成功或已完成的任务时，复制其完整 `CheckItemResult` 和原始结果路径，记录 `reused_shared_water_check`、`shared_check_owner_layer`；否则执行算法。
3. 将每个任务结果保存在 `WaterTaskRun`，供当前地图任务全部完成后分类输出。失败结果不作为可复用的成功结果。

相对于备份，原先只针对当前任务直接调用算法并记录结果的路径，被扩展为“判断可否复用 → 执行或复用 → 保存 → 统一汇总”。实际签名逻辑见 `ui_class/line_topology_shared_tasks.h`。

### 3.4 按类别分发、去重、输出及计数

新增 `consolidateWaterTaskResults(...)` 及相关辅助函数，主要步骤：

1. 读取成功或完成的水系任务的中间 SHP 和 JSON 错误；不能读取的文件加入诊断信息。
2. `waterCategoryFromFields(...)` 优先读取 `ref_class`，再将 `ref_value` 交给类别映射函数按 `LEVEL`／`TYPE` 尝试解析；不能确定或候选冲突时归入“水系待归类”。JSON 分支使用对应的 `reference_*` 字段。
3. `waterFeatureFingerprint(...)` 对错误字段、`detail_*` 字段及几何 WKB 的 SHA-256 生成指纹；JSON 使用剔除参考分类字段后的内容生成指纹。在各自任务组内合并重复记录。**相反方向的要素对描述、几何或其他指纹字段不同，仍可能保留两条记录。**
4. 按检查 ID、类别、点／线／面分别写出 SHP。写出前尝试在主线程卸载相关旧结果图层，再清理相应 SHP 配套文件；失败记入诊断，不能视为全局事务。
5. 将已归类记录分配给相应标准图层任务，待归类 JSON 记录归给该组第一个成功任务，避免每个标准图层都计数一次；更新错误数、错误类型、结果路径及最终 JSON。日志从暂存目录复制到最终目录。
6. 生成 `water_result_classification` 汇总，记录分组、类别、错误数、要素数、结果路径和待归类项；`generateJsonData()` 在该汇总非空时写入总 JSON。

### 3.5 直角化共享

相对于备份，增加 `RightAngleSharedTasks::Cache`：每幅地图执行时创建；根据输入、检查规则和比例尺形成键。缓存命中时跳过重复运算，调用 `writeReusedOutput(...)` 写入复用引用；未命中时运行算法，并在可复用时保存结果。缓存作用域为当前地图的本次执行。

### 3.6 同名输出的替换及路径回写

在 `archiveErrorLayersBySeverity(...)` 中，相对于备份：

- 对 SHP 且 `CheckResultReplacement::supports(...)` 支持的结果，在严重程度目录中通过 `owns(...)` 找出旧文件，先复制到 `QTemporaryDir`；在 GUI 线程卸载旧图层，再尝试删除旧文件。
- 备份、卸载或删除失败时跳过或尝试恢复；恢复失败时保留临时备份并输出警告。
- 继续执行原有的目标路径选择和复制归档；如果目标文件仍存在，代码仍有 `_2`、`_3` 等后缀回退。
- 新增把归档后的路径替换进 `m_waterClassificationSummary` 和结果目录下 JSON 的处理，使用 `QSaveFile` 写回。

之前另一轮的图层组归档与补载工作已存在于本次 CPP 备份中，因此**不显示为上述 893／15 差异**。历史记录见根目录 `质检任务管理代码修改说明.md`；不要把该记录误认为本次备份之后的逐行差异。

## 5. `map_check_algorithms.cpp`

相对于 `tmp/road_topology_before_20261030/map_check_algorithms.cpp`，完整差异有三处：

### 5.1 修改输出目录选择

`CreateOutputDirectories(...)` 中原先无条件使用 `质检错误结果`；当前当 `baseOutputDir` 包含 `.water_task_results_` 时使用 `water_work`，否则继续使用原目录名。相关目录仍由 `QDir().mkpath(...)` 创建。

### 5.2 修改 112 缺少成果输入时的返回值

`checkLineTopology(...)` 中 `actualShpSemicolon.isEmpty()` 分支删除原来的“质检成功／无错误／实际图层不存在”返回，改为“质检失败／存在问题”，并在 `description` 和 `summary` 中说明未找到匹配成果线图层、检查未执行。

### 5.3 新增 112 图层专属 XML 规则校验

`MatchXmlByLayerName(...)` 之后、创建输出目录之前新增校验：XML 文件基本名必须等于 `standardLayer`，文件可打开且可解析，存在 ID 为 `112` 且名称与当前检查项相同的 `check_item`。不满足时提前返回失败，并在 `info.xml_path` 中记录选中的路径。

这会拒绝使用通用命名的 XML 或名称不一致的 112 规则；其他检查入口仍沿用各自逻辑。旧说明 `map_check_algorithms_本次对话修改说明.md` 写于较早时间，只列出了后两处，未包含后来的 `water_work` 变动；以本报告和 diff 为准。
